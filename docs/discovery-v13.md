# MING EAGLE 客户发现 V13.1

这次更新针对美国市场的静音篮球采购群体，扩展搜索覆盖和候选管理。客户发现仍以公开地点和官网资料为依据；评分表示跟进优先级，不代表客户已经有采购意向。

## 新增能力

- 16 类客户：保留原有商业与学校类别，新增独立篮球教练、多项目体育训练机构、社区体育中心 / YMCA、体育用品批发商、篮球 / 体育夏令营。
- 美国 50 州共用城市库；可填写英文城市名称，覆盖主要城市以外的市场。
- 每次成功搜索自动进入下一批，轮换城市和关键词，减少重复搜同一组查询。
- Geoapify 原有文字地点搜索增加 Places 类别检索。每批最多查询两个城市的体育中心 / 体育馆或体育用品店，继续核验目标业务。
- 官网核验增加各类别的业务证据、地区证据和采购使用场景；缺少公开直接联系方式的新版商业候选评分最高为 B 级。
- 以候选记录 ID 统计每次真正新增、已有更新和优先跟进数量，跨来源重复结果只计算一次。
- 已忽略候选不会因重复搜索重新进入待开发；CRM 中的记录不会被发现流程恢复为新客户。
- 按州、类型、评分、状态、联系方式完整度和文字查询筛选；候选库分页，每页 50 个，支持导出当前页 CSV。
- 单个数据源失败时显示来源状态和错误，并保留另一个来源的结果；全部失败不会报告成功。

## 推荐使用顺序

1. 优先搜索篮球训练机构、独立教练、社区体育中心，再拓展零售商、批发商、夏令营和学校。
2. 选择州和客户类别，先运行一批；若要开发某个城市，填写如 Dallas 的英文城市名。
3. 同一组条件重复点击搜索，系统继续下一批。切换州、类别或城市时从第一批开始。当前批次保留于当前页面会话。
4. 在名单中筛选“优先跟进 · A 级且可联系”，核对官网及来源证据。
5. 对待补全客户使用“官网补全”或批量补全前 5 个；负责人信息仅来自公开网页。
6. 确认适合的候选后加入 CRM。导出的是当前筛选页面，若有多页需要分别导出。

每批 20 / 50 / 100 是目标数量。免费或已有接口配额、官网可访问性和可核验结果会限制实际返回数量；不保证每批达到目标。搜索与入库流程本身不会发送消息。网站原有的独立销售自动化设置由原流程管理。

## 来源及技术边界

- 地点：Geoapify Geocoding、Places、Place Details；需要后台已有 GEOAPIFY_API_KEY。
- 官网：公开 Web 搜索得到的网站，通过机构身份、实际业务及地区信息验证。
- 学校：保留学校 / 学区专用发现，检查公开学校、体育和采购资料。
- 不新增付费搜索服务、不购买名单、不生成猜测邮箱。范围仍以美国市场为主。
- 查询计划会循环轮换，不是互联网全量客户数据库；公开搜索和地点覆盖无法保证穷尽所有机构。

接口参考：[Geoapify Places](https://apidocs.geoapify.com/docs/places/)。

执行 npm run build、npm run test:discovery 和 Cloudflare Functions 打包。

模拟网络与 SQLite 数据库集成测试覆盖：50 州查询、新类别业务核验、跨来源去重、新增与更新统计、忽略保护、空联系方式修复、学校 SQL、单源 / 全源失败、分页、筛选、CRM 重复导入和 CSV 安全导出。

## V13.1 真实验收修正

- 2026-10-07 真实 Dallas 搜索发现：Geoapify 文字地理编码会返回普通篮球场、篮球架、饮水点，甚至 Austin 的结果。商业候选现在必须通过公开官网业务核验；设施名称不直接作为购买机构。填写城市时地点及学校结果必须匹配该城市。
- Web 城市核验必须在官网正文找到城市，州名不再替代城市条件。官网中的城市仅表示其提及的服务范围，不应视为已核实的注册地址。
- 新增“官网批量核验”：使用上方州、商业类型及城市条件，每次最多 10 个公开官网，每行一个。自动识别机构、核验业务及地区、提取公开联系方式、按域名去重，并报告未通过或保持忽略的结果。来源明确标为“官网导入核验”。
- 百科、教程、新闻、社交及目录平台不作为官网候选。公开网页读取限制重定向次数、大小和时间，拒绝本地及私有地址。
- “已忽略”新增“恢复候选”；恢复已有 CRM 关联时保持 CRM 状态。旧 SEARCH 接口统一转向当前核验流程。
- 新增回归测试覆盖错误城市、无官网地点、设施误识别、官网批量核验、百科过滤、私有地址及重定向拒绝、忽略恢复。
- 公开自动搜索仍受搜索供应商实际覆盖限制；自动查询无有效结果时可使用公开搜索或行业目录找到官网，再通过新增入口核验。系统不会用未核验名单填满每批目标。
